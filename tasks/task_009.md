# Задача 009: Мультиязычный интерфейс (i18n: en/ru)

## 1. Цель
Ввести локализацию интерфейса и пользовательских сообщений: английский язык по умолчанию, русский как второй, переключение без изменения URL, расширяемый набор локалей. Вынести все пользовательские строки из Blade-шаблонов, контроллеров, Policy и исключений в lang-файлы; локализовать валидацию, flash-сообщения, ошибку `409`, письма и подписи PDF/HTML. Закрыть пересмотренное решение №10 из `questions.md`.

## 2. Зависимости
- Завершены задачи 001–008: экраны и сообщения уже существуют, задача переводит и выносит готовые строки.
- Пересмотр решения №10 зафиксирован в `questions.md`, политика языка — в `technical.md` §«Язык интерфейса и данных».
- Не блокирует `task_000`; выполняется до финальной приёмки.
- Схема БД не меняется, миграции не нужны.

## 3. Требования к реализации

### 3.1. Локали и конфигурация
- `config/locales.php`:
  - `supported` — `['en', 'ru']`;
  - `default` — `'en'`, `fallback` — `'en'`;
  - `cookie` — `'locale'`, срок жизни — 1 год (`525600` минут);
  - `names` — отображаемые названия языков (`English`, `Русский`) для переключателя.
- `config/app.php`: `locale` и `fallback_locale` берутся из `APP_LOCALE`/`APP_FALLBACK_LOCALE`; значения по умолчанию — `en`.
- `.env.example`: `APP_LOCALE=en`, `APP_FALLBACK_LOCALE=en`.
- Новая локаль добавляется записью в `supported`, файлами `lang/<locale>/` и `lang/<locale>.json`; правки кода не требуются.

### 3.2. Определение и переключение языка
- Middleware `App\Http\Middleware\SetLocale` в группе `web` после `StartSession`:
  - порядок разрешения: `session('locale')` → `cookie('locale')` → `config('locales.default')`;
  - значение проверяется по `supported`; неизвестное — молча откатывается к `en`;
  - вызывает `App::setLocale($locale)` и `Carbon::setLocale($locale)`;
  - язык запроса не влияет на права, данные, расчёты и audit-логи.
- Маршрут `GET /locale/{locale}`, имя `locale.update`, доступ — все роли и гости, `whereIn` по `supported`; неизвестная локаль — `404`:
  - сохраняет выбор в сессию и cookie на год;
  - возвращает `redirect()->back()` с fallback на `route('dashboard')`/`route('welcome')`; query-строка сохраняется.
- Переключатель `EN | RU`:
  - в `layouts/navigation.blade.php` (авторизованные) и `layouts/guest.blade.php` (гости);
  - активный язык подсвечен, `aria-current`, `hreflang`, `lang` на ссылках;
  - на мобильных — в раскрывающемся меню, не перекрывает навигацию;
  - переключение — GET-ссылка: не отправляет формы и не теряет введённые данные.
- `<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">` во всех layout'ах.
- Cookie — стандартная зашифрованная cookie Laravel, `SameSite=Lax`, без чувствительных данных.
- HTML-ответы зависят от cookie: middleware добавляет заголовок `Vary: Cookie`; reverse proxy/CDN не кэширует HTML без него, требование фиксируется в runbook `task_000`.

### 3.3. Файлы переводов и вынос строк
- `lang/en/` и `lang/ru/` — группы: `common`, `nav`, `auth`, `profile`, `players`, `tournaments`, `admin`, `errors`, `exports`, `mail`, `pagination`, `passwords`, `validation`.
- `lang/en.json`, `lang/ru.json` — встроенные строки Laravel (уведомление о сбросе пароля, подтверждение email и т.п.).
- Все пользовательские строки выносятся из:
  - Blade-шаблонов, включая `welcome`, `dashboard`, `profile`, `auth/*`, `errors/409`, экспортные шаблоны;
  - контроллеров, Form Request, Policy, middleware и `bootstrap/app.php` (сообщение `409`);
  - flash-сообщений, `withErrors` и заголовков страниц.
- Правила:
  - ключи иерархические: `players.index.title`, `tournaments.status.in_progress`;
  - переведённые фрагменты не конкатенируются; параметры — `:name`, `:count`;
  - склонения — `trans_choice` (`ru` — формы 1/2/5, `en` — 1/other);
  - пользовательские данные (ФИО, названия турниров, примечания) не переводятся;
  - машинные значения не переводятся: статусы `draft`/`in_progress`/`completed`, режимы `average`/`per_game`, коды ошибок, заголовки XLSX/CSV, поля audit-лога; для UI используются подписи из lang.
- Даты и время: формат по локали (`d.m.Y` для `ru`, `M j, Y` для `en`), названия месяцев и дней — через Carbon locale. Числа и рейтинги остаются целыми без разделителей; язык не меняет вычисления.
- Файлы — UTF-8 без BOM.

### 3.4. Валидация, flash, ошибки и письма
- Form Request: `messages()` и `attributes()` через `__()`; общие правила — в `lang/{en,ru}/validation.php`.
  - Минимальный набор правил: `required`, `string`, `integer`, `numeric`, `boolean`, `array`, `email`, `date`, `date_format`, `after_or_equal`, `before_or_equal`, `unique`, `exists`, `in`, `max`, `min`, `between`, `size`, `confirmed`, `current_password`, `password`, `image`, `mimes`, `file`, `regex`.
  - Незаданные правила отдают fallback `en`; `attributes` покрывают поля `name`, `email`, `password`, `birth_date`, `current_rating`, `tournament_id` и другие используемые поля.
- `lang/{en,ru}/auth.php`, `passwords.php`, `pagination.php`.
- Flash-сообщения и сообщения Policy — через `__()`.
- `ConcurrentModificationException`: исключение хранит только признак конфликта; текст «Данные изменились, обновите страницу» / "The data has changed, please refresh the page" берётся из lang в обработчике `bootstrap/app.php`; JSON-ответ локализуется по языку запроса.
- Письма: тексты писем и уведомлений (сброс пароля, подтверждение email) — в `lang/{en,ru}` и JSON-файлах; локаль письма равна локали запроса на момент отправки; при постановке в очередь локаль фиксируется (`Mail::locale()`/`->locale()`).
- Ограничение: `users.locale` не вводится (см. §7) — письмо получателю уходит на языке инициатора действия.

### 3.5. Экспорты и печатные формы
- PDF/HTML-шаблоны (`players/export-*`, `tournaments/export-*`): заголовки, подписи колонок, режим расчёта, футер и дата — по локали запроса.
- XLSX/CSV/ODS: машинные заголовки — латиницей и не локализуются; человекочитаемая шапка листа — по локали.
- Язык фиксируется в момент экспорта; повторный экспорт после переключения языка выполняется на новом языке.
- Импорт: отчёт «Успешно импортировано: N, с ошибками: M» и причины ошибок строк — по локали; кодировка файла (UTF-8/Windows-1251) от локали не зависит.
- PDF-шрифт поддерживает латиницу и кириллицу (обеспечено в `task_003`/`task_007`); локали с иной письменностью требуют отдельного шрифта и проверки.

## 4. Критерии приемки (DoD)
1. Первый визит без cookie и сессии — английский интерфейс; переключение на русский сохраняется в сессии и cookie и переживает закрытие браузера.
2. `/locale/xx` возвращает `404`; неизвестный код в cookie/сессии не ломает приложение и откатывается к `en`.
3. Все экраны 001–008 (auth, profile, players, tournaments, admin, errors, exports) не содержат захардкоженных пользовательских строк; кириллица в `resources/views` и `app` отсутствует (кроме `lang/`, `config/locales.php` и тестов).
4. Валидация, flash, сообщения Policy, страница `409` и письма отображаются на выбранном языке.
5. PDF/HTML-экспорты локализованы; заголовки XLSX/CSV остаются латиницей.
6. Недостающий ru-ключ отдаёт английскую строку; сырые ключи вида `players.index.title` в UI не появляются.
7. Паритет ключей `en`/`ru` подтверждён тестом; добавление локали проверено тестом без изменений кода — только `config/locales.php` и файлы переводов.
8. Существующие тесты обновлены и зелёные; `php artisan test`, `npm run build`, `vendor/bin/pint --test`, `php artisan migrate:fresh --seed` проходят.

### 5.2. Автотесты
- Feature `SetLocaleTest`: язык по умолчанию `en`; cookie; сессия; приоритет сессии над cookie; неизвестная локаль; `/locale/{locale}` и редирект с сохранением query; заголовок `Vary: Cookie` на HTML-ответах.
- Feature `LocalizationTest`: паритет ключей `en`/`ru`; отсутствие кириллицы в Blade и `app`; отсутствие сырых ключей в HTML; `trans_choice` для `ru` (1/2/5) и `en`.
- Feature: страницы auth, players, tournaments, admin в обеих локалях — `200` и ожидаемые подписи через `__()`.
- Feature: валидация — невалидный POST на `ru` и `en` возвращает локализованные сообщения.
- Feature: `409` — HTML-страница и JSON-ответ на языке запроса.
- Feature: письма — сброс пароля и подтверждение email содержат локализованный текст при `ru` (`Mail::fake()`/`Notification::fake()`).
- Feature: экспорт — PDF/HTML содержит локализованные подписи; XLSX-заголовки остаются латиницей (чтение через PhpSpreadsheet).
- Regression: существующие feature-тесты, проверяющие русские подписи, переведены на `__()` или языконезависимые селекторы; весь набор 001–008 зелёный.

## 6. Риски и допущения
- Риск пропуска захардкоженных строк закрыт статическим автотестом на отсутствие кириллицы в `app/` и `resources/views/`, проверкой отсутствия BOM и проходом основных экранов на утечку сырых ключей.
- Существующие feature- и unit-тесты переведены с захардкоженных русских UI-подписей на `__()` и `label()` enum'ов; тестовые пользовательские данные (ФИО, названия турниров) сохранены на кириллице для проверки кодировок.
- Паритет ключей `en`/`ru` (включая `en.json`/`ru.json`, `attributes` и обязательный набор правил `validation.php`) проверяется автоматически в `LocalizationTest`; недостающие правила `validation.php` безопасно откатываются на `en`.
- HTML-ответы снабжаются заголовком `Vary: Cookie` в `SetLocale`; запрет кэширования HTML без `Vary: Cookie` на уровне прокси/CDN учтён в `task_000.md`.
- Язык уведомлений (`ResetPassword`, `VerifyEmail`) фиксируется вызовом `->locale(app()->getLocale())` в момент отправки; без `users.locale` письмо отправляется на языке инициатора запроса.
- Человекочитаемые даты форматируются через `App\Support\DateFormatter` по шаблонам из `config/locales.php` (`M j, Y` для `en`, `d.m.Y` для `ru`), а машинные значения (ISO-даты, заголовки и коды в XLSX/CSV, `code` в JSON `409`, записи логов) не локализуются.
- PDF-шрифт (`DejaVu Sans`) покрывает латиницу и кириллицу; локали с иной письменностью (арабица, CJK) потребуют отдельного шрифта.
- Переключение языка — GET-ссылка без CSRF, ограниченная `whereIn` по `config('locales.supported')`; при отсутствии `Referer` или если предыдущий URL указывал на `/locale/*`, контроллер безопасно перенаправляет на главную или `dashboard`.
- Локализация не меняет права, расчёты Elo, tiebreak и схему БД.
