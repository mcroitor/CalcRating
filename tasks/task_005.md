# Задача 005: Жеребьевка турниров (Круговая, Олимпийская, Швейцарская)

## 1. Цель
Разработать сервис автоматической жеребьевки и генерации партий (`PairingService`) для трех систем проведения соревнований: круговой, олимпийской и швейцарской.

## 2. Зависимости
- Выполнена Задача 004 (модели турниров, участников и статусов).

## 3. Требования к реализации

### 3.1. Структура данных
- Таблица `pairings` (партии / расписание туров):
  - `id` (bigint, PK)
  - `tournament_id` (bigint, fk к `tournaments`, cascade on delete)
  - `round_number` (integer) — номер тура (1..N)
  - `board_number` (integer) — номер стола/партии в туре
  - `white_player_id` (bigint, fk к `players`) — белые (участник 1)
  - `black_player_id` (bigint, nullable, fk к `players`) — черные (участник 2, null при bye)
  - `result` (string, default: `*`) — результат: `1-0`, `0-1`, `1/2-1/2`, `0-0`, `*` (не сыграно)
  - `advanced_player_id` (bigint, nullable, fk к `players`) — участник, проходящий дальше (для олимпийской системы при ничьей)
  - `version` (unsigned integer, default: 1) — версия для оптимистичной блокировки
  - `timestamps`

### 3.2. Алгоритмы генерации туров

#### 1. Круговая система (Round-robin)
- Алгоритм таблиц Бергера:
  - Все $N-1$ туров (или $N$, если число участников нечетное) могут генерироваться единовременно при старте турнира.
  - При нечетном количестве участников добавляется фиктивный игрок («выходной» / bye).
  - Учет `games_per_round`: если указано 2 партии, создается ответная встреча со сменой цвета фигур.

#### 2. Олимпийская система (Knockout)
- Число участников дополняется до ближайшей степени двойки ($2, 4, 8, 16, 32$) или игроки с высшим рейтингом пропускают первый раунд.
- Посев первого раунда: 1-й по рейтингу против последнего, 2-й против предпоследнего.
- Генерация следующего раунда доступна только после завершения всех партий текущего раунда.
- **Разрешение ничьих:** Если сумма очков в паре равна (например, `1/2-1/2` или `1-1` при 2 партиях), судья вручную выставляет победителя пары (`advanced_player_id`), который попадает в следующий круг.

#### 3. Швейцарская система (Swiss)
- Генерация происходит строго по турам (тур $K+1$ генерируется только после окончания всех партий тура $K$).
- Упрощенный жадный алгоритм:
  1. Участники сортируются по убыванию набранных очков; при равенстве — по текущему рейтингу (для целей жеребьевки). Итоговая турнирная таблица использует отдельную цепочку tiebreak из `task_004`.
  2. Формируются пары сверху вниз.
  3. **Запрет повторов:** Проверяется, что данная пара еще не играла между собой в предыдущих турах этого турнира. Если играла — берется следующий подходящий соперник.
  4. При нечетном количестве участников игроку из нижней части таблицы, еще не получавшему свободный тур, присваивается bye (`black_player_id = null`, результат автоматически `1-0` или +1 очко).

### 3.3. Пользовательский интерфейс
- Вкладка «Жеребьевка и туры» в карточке турнира.
- Кнопка «Сгенерировать тур N» (активна только для судьи и админа при завершении предыдущего тура).
- Отображение партий тура в виде таблицы: Доска, Белые, Результат, Черные.
- Для олимпийской системы: радиокнопка выбора победителя при равенстве очков.
- Сохранение результата и `advanced_player_id` выполняется с проверкой `pairings.version`; при конфликте — `409 Conflict`.
- Итоговая турнирная таблица сортируется по цепочке tiebreak из `task_004`: очки ↓ → личная встреча (только при равенстве двух участников) → число побед ↓ → стартовый рейтинг ↓ → ID шахматиста ↑.
- Для олимпийской системы места определяются стадией выбывания; сортировка по очкам применяется только внутри группы участников, выбывших на одном раунде.

### 3.4. Подзадачи реализации
- [x] **5.1. Модель `Pairing` и миграция:** Создание таблицы `pairings`, Eloquent-связей с `Tournament` и `Player` (белые, черные, победитель).
- [x] **5.2. Круговая жеребьевка (`RoundRobinGenerator`):** Реализация алгоритма вращения Бергера, распределение белого/черного цвета, генерация ответных партий при `games_per_round = 2`.
- [x] **5.3. Олимпийская жеребьевка (`OlympicGenerator`):** Посев участников по рейтингу для 1-го раунда, формирование последующих раундов по парам победителей, логика выбора победителя при ничьей (`advanced_player_id`).
- [x] **5.4. Швейцарская жеребьевка (`SwissGenerator`):** Жадная группировка по очкам, проверка истории очных встреч в текущем турнире, начисление `bye` (+1 очко) при нечетном составе.
- [x] **5.5. Контроллер и UI управления турами:** Экшен генерации очередного тура с проверкой завершения предыдущего, отображение расписания партий по турам и доскам.
- [x] **5.6. Турнирная таблица и tiebreak:** Сервис построения итоговой таблицы с детерминированной цепочкой tiebreak; для олимпийской системы — ранжирование по стадии выбывания.
- [x] **5.7. Оптимистичная блокировка партий:** Проверка `pairings.version` при сохранении результата и выборе проходящего участника, обработка `409`.

## 4. Критерии приемки (DoD)
1. Для круговой системы генерируется полное расписание, в котором каждый участник играет с каждым ровно один раз (или два при `games_per_round = 2`).
2. Для олимпийской системы победители формируют сетку следующего раунда; при ничьей блокируется генерация следующего тура до указания судьей проходящего игрока.
3. В швейцарской системе ни одна пара игроков не встречается дважды за турнир; при нечетном числе корректно начисляется bye.
4. Гости видят расписание туров и досок, но не имеют доступа к кнопке генерации.
5. Итоговая турнирная таблица сортируется по детерминированной цепочке tiebreak; при равенстве трех и более участников личная встреча не применяется.
6. При конкурентном изменении результата партии второе сохранение возвращает `409` и не перезаписывает результат.

## 5. Проверка и тесты
- Unit-тест генерации круговой системы на 4 и 5 участников (проверка отсутствия дубликатов встреч).
- Unit-тест швейцарской жеребьевки на 3 тура для 8 игроков: проверка на отсутствие повторных пар.
- Unit-тест валидации генерации следующего раунда в олимпийской системе при ничейном счете.
- Unit-тест: при равенстве очков места распределяются по цепочке tiebreak; порядок стабилен при повторных запросах.
- Feature-тест: конфликт версий при одновременном сохранении результата партии.

## 6. Риски и допущения

- Жадный швейцарский алгоритм может не найти допустимую пару; используется детерминированный fallback без повторного соперника, если он возможен.
- Выбор bye и баланс цвета могут приводить к повторным bye или нежелательному распределению цветов; повторный bye исключается, пока есть участник без bye.
- Олимпийская сетка при числе участников не степени двойки дополняется bye по стандартному посеву; сильнейшие получают bye в первых парах сетки.
- Ничья и `0-0` в олимпийской системе блокируют следующий раунд до выбора `advanced_player_id`; UI и сообщение об ошибке явно указывают на это.
- Генерация и отображение больших турниров могут быть медленными; связи `pairings` загружаются eager loading, расписание группируется по турам.
- `games_per_round = 2` применяется к круговой системе (ответные партии со сменой цвета); для швейцарской и олимпийской систем используется одна партия за тур.
- При нечётном числе участников круговой системы один участник отдыхает в туре и не получает бонусное очко; в швейцарской системе bye даёт +1 очко, в олимпийской bye автоматически проводит в следующий раунд.

## 7. Открытые вопросы

- Строгий алгоритм FIDE и floating не реализованы: используется упрощённая детерминированная жеребьёвка.
- Цветовые предпочтения и чередование цветов в швейцарской системе не отслеживаются: белые — первый участник пары после сортировки.
- Ручное редактирование пар после генерации не поддерживается; доступны генерация и ввод результатов.
- Участники, выбывшие на одном раунде олимпийской системы, ранжируются по очкам и полной цепочке tiebreak.
- `games_per_round > 1` для швейцарской и олимпийской систем не поддерживается.

## 8. Реализация

- `pairings` + `Pairing` с `version`; связи `Tournament::pairings()`, `Pairing::whitePlayer/blackPlayer/advancedPlayer`.
- `RoundRobinGenerator` — полное расписание Бергера; `SwissGenerator` — один тур по очкам/рейтингу с запретом повторов и bye; `OlympicGenerator` — стандартный посев сетки и генерация следующего раунда по победителям.
- `PairingService` оркестрирует генерацию и сохранение результатов в `DB::transaction()`, пересчитывает очки участников из всех партий и увеличивает `tournament_participants.version` при изменении очков; генерация использует CAS по `tournaments.version`, сохранение результата — CAS по `pairings.version`.
- `PairingController` + Policy `managePairings`: генерация и ввод результатов только для `arbiter`/`admin` при статусе `in_progress`; гости видят расписание и таблицу.
- `StandingsService` учитывает победы, личные встречи и стадию выбывания в олимпийской системе.
- Удаление шахматиста запрещено при участии в турнире `in_progress`/`completed` (Policy и `PlayerService`).
