# Задача 002: Модуль управления шахматистами и карточка с графиком рейтинга

## 1. Цель
Реализовать учет шахматистов, хранение истории изменения их рейтинга, интерфейсы CRUD (с учетом прав доступа) и личную карточку игрока с интерактивным графиком изменения рейтинга.

## 2. Зависимости
- Выполнена Задача 001 (авторизация, роли, базовая верстка).

## 3. Требования к реализации

### 3.1. Структура данных
- Таблица `players`:
  - `id` (bigint, PK) — идентификатор/номер шахматиста
  - `first_name` (string) — имя
  - `last_name` (string) — фамилия
  - `birth_date` (date) — дата рождения
  - `title` (enum: `None`, `IV`, `III`, `II`, `I`, `CM`, `WCM`, `FM`, `WFM`, `IM`, `WIM`, `GM`, `WGM`)
  - `current_rating` (integer, default: 1000) — текущий рейтинг
  - `notes` (text, nullable) — дополнительная информация
  - `version` (unsigned integer, default: 1) — версия для оптимистичной блокировки
  - `timestamps`
- Таблица `ratings` (история изменений):
  - `id` (bigint, PK)
  - `player_id` (fk к `players`, restrict on delete)
  - `tournament_id` (bigint, nullable) — турнир, по итогам которого изменен рейтинг; внешний ключ к `tournaments` с `ON DELETE SET NULL` добавляется миграцией в Задаче 004
  - `value` (integer) — зафиксированное значение рейтинга
  - `created_at` (timestamp) — дата и время фиксации

### 3.2. Логика и контроллеры
- При создании шахматиста автоматически создается начальная запись в таблице `ratings` с его стартовым рейтингом.
- Обновление карточки игрока выполняется с проверкой `version` (compare-and-swap); при конфликте — `409` и сообщение «Данные изменились, обновите страницу».
- Запрещено прямое ручное редактирование истории рейтингов (старые записи неизменяемы).
- Удаление игрока разрешено только при отсутствии турнирной рейтинговой истории и участия в турнирах `in_progress`/`completed` (см. `questions.md` №9). Начальная запись `ratings` удаляется в той же транзакции; `ratings.player_id` — `ON DELETE RESTRICT`.
- Фильтрация и поиск в общем списке шахматистов: по фамилии, имени, титулу, диапазону рейтинга.
- Пагинация списка (по 15–25 записей).

### 3.3. Пользовательский интерфейс (Blade + Tailwind)
- Адаптивный список шахматистов: таблица на десктопе, компактные карточки на мобильных устройствах.
- Кнопки добавления, редактирования и удаления отображаются только для пользователей с ролями `arbiter` и `admin`.
- Личная карточка шахматиста (`/players/{id}`):
  - Анкетные данные, возраст, титул, текущий рейтинг.
  - Таблица истории изменений рейтинга (дата, турнир, значение, разница +/-).
  - График динамики рейтинга с использованием Chart.js (линейный график по точкам из `ratings`). Chart.js устанавливается через npm и импортируется в `resources/js/app.js`; сборка выполняется через Vite, CDN не используется.

## 4. Критерии приемки (DoD)
1. Гость может просматривать список шахматистов и карточку любого игрока.
2. Судья и Администратор могут добавлять и редактировать шахматистов, а также удалять игрока без турнирной рейтинговой истории и участия в `in_progress`/`completed`; при наличии истории удаление запрещено.
3. Валидация форм: обязательные поля, корректность даты рождения, допустимые значения титулов, рейтинг >= 0.
4. В карточке шахматиста корректно отображается график динамики рейтинга.
5. Время отклика страницы со списком при 1000+ игроках не превышает 500 мс.
6. При конкурентном редактировании игрока второе сохранение не перезаписывает первое, а возвращает `409` с просьбой обновить данные.

## 5. Проверка и тесты
- Unit-тест: создание игрока создает начальную запись в `ratings`.
- Feature-тест: CRUD-операции над игроками с проверкой прав доступа (гость не может создать/изменить/удалить).
- Feature-тест: удаление игрока без турнирной истории разрешено и удаляет начальную запись `ratings`; удаление игрока с турнирной историей или участием в `in_progress`/`completed` запрещено.
- Feature-тест: конфликт версий при одновременном редактировании игрока.

## 6. Риски и допущения

- Удаление игрока с турнирной рейтинговой историей или участием в `in_progress`/`completed` запрещено; начальная запись `ratings` удаляется вместе с игроком. Мягкое удаление в MVP не применяется (см. `questions.md` №9).
- `players.current_rating` должен совпадать с последней записью `ratings`; ручное редактирование рейтинга может нарушить эту инварианту.
- Chart.js увеличивает размер JS-бандла; импортировать только необходимые модули.
- Поиск и фильтрация при 1000+ игроках требуют индексов по фамилии, имени, титулу и рейтингу.
- Дата рождения хранится как `date`; возраст рассчитывается на дату турнира, а не на текущую дату.
- Предполагается, что ID игрока выполняет роль «Номера шахматиста» из ТЗ.
