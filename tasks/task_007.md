# Задача 007: Экспорт турнирной таблицы и результатов (PDF, XLSX, HTML)

## 1. Цель
Реализовать выгрузку итоговой турнирной таблицы и протоколов встреч в форматы PDF, XLSX и HTML для печати и распространения, а также провести финальный аудит нефункциональных требований (производительность, адаптивность интерфейса).

## 2. Зависимости
- Выполнены Задачи 003, 004, 005, 006 (генерация файлов, завершенные турниры с результатами и рейтингами).

## 3. Требования к реализации

### 3.1. Форматы экспорта турнира
- Доступны для ролей `arbiter` и `admin`.
- **Состав выгружаемых данных:**
  - Шапка: название турнира, даты, место проведения, ФИО главного судьи, система жеребьевки, режим расчета рейтинга (`average` / `per_game`).
  - Итоговая турнирная таблица: Место, Имя и фамилия, Титул, $R_{до}$, Набранные очки, $R_{после}$, Изменение рейтинга ($\Delta$).
  - Сетка туров / партий: по турам со списком партий, цветов фигур и зафиксированных счетов.
  - Места в итоговой таблице рассчитываются по цепочке tiebreak из `task_004`; для олимпийской системы — по стадии выбывания. Экспорт использует уже рассчитанные места и не пересчитывает их по-своему.
- **Форматы:**
  - **XLSX:** структурированный лист с форматированием заголовков, границами ячеек и автошириной колонок (`maatwebsite/excel`).
  - **PDF:** официальный судейский протокол в книжной или альбомной ориентации (`barryvdh/laravel-dompdf`), поддержка кириллицы.
  - **HTML:** чистый шаблон протокола с CSS-стилями для печати (`@media print`), кнопкой «Печать / Сохранить в PDF» через браузер.
- Подписи и тексты протокола локализуются по языку запроса (`task_009`); машинные заголовки XLSX остаются латиницей.

### 3.2. Аудит нефункциональных требований
- **Адаптивность (RWD):**
  - Проверка отображения турнирных таблиц на смартфонах (горизонтальная прокрутка или компактный вид досок без поломки разметки).
- **Производительность:**
  - Время генерации отчетов и отклика всех страниц $\le 5$ секунд (согласно ТЗ). Оптимизация запросов через eager loading (`with(['players', 'pairings'])`) во избежание проблем $N+1$.

### 3.3. Подзадачи реализации
- [x] **7.1. Экспорт в XLSX (`TournamentExport`):** Создание экспорта турнирной таблицы и результатов туров с форматированием колонок.
- [x] **7.2. Экспорт в PDF:** Шаблон `tournaments.export-pdf`, верстка судейского протокола и результатов партий, генерация через DomPDF с поддержкой UTF-8.
- [x] **7.3. HTML-версия для печати:** Шаблон `tournaments.export-html` без боковых панелей с оптимизированными CSS стилями `@media print`.
- [x] **7.4. Проверка прав и контроллер экспорта:** `TournamentExportController`, ограничение доступа по ролям (только `arbiter` и `admin`).
- [x] **7.5. Аудит производительности и адаптивности:** Проверка запросов к БД на отсутствие $N+1$ (eager loading связей турнира), тест адаптивности на экранах смартфонов и планшетов.

## 4. Критерии приемки (DoD)
1. Судья и Администратор могут в один клик скачать турнирный отчет в форматах `.xlsx`, `.pdf` или открыть версию `.html`.
2. Гость при попытке прямой загрузки файлов по URL получает `403 Forbidden`.
3. PDF-документ корректно форматируется на русском языке без кракозябр и наложения текста.
4. В отчете корректно отображаются набранные очки (включая половинчатые значения `0.5`, `1.5` и т.д.) и изменение рейтинга.
5. Время генерации PDF-файла турнира на 30+ участников укладывается в 2 секунды.

## 5. Проверка и тесты
- Feature-тест скачивания отчетов турнира в форматах PDF, XLSX и HTML с проверкой прав доступа.
- Тест корректности данных в выгружаемом файле (проверка соответствия очков и дельты рейтинга данным в БД).
- Тест: места в выгружаемом файле соответствуют цепочке tiebreak из `task_004`, включая случай равенства трех и более участников.
- Тест: в шапке выгрузки указан режим расчета рейтинга турнира (`average` / `per_game`).

## 6. Риски и допущения

- PDF с кириллицей требует встроенного UTF-8 шрифта; возможны проблемы с переносами и пагинацией больших таблиц.
- Экспорт больших турниров может вызвать N+1 и превышение времени; обязательны eager loading и ограничение выборки.
- Прямой доступ к URL экспорта должен проверять права; гость получает `403`.
- XLSX/CSV должны быть защищены от formula injection.
- Имена файлов должны быть безопасными и содержать название турнира/дату.
- Предполагается, что экспорт доступен как для завершенных, так и для идущих турниров; для незавершенного турнира `rating_after` и итоговые места могут отсутствовать, а режим расчета известен всегда, так как фиксируется при старте турнира (в `draft` может меняться, после старта — нет).
